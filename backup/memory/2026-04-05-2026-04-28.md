## 📺 Andrej Karpathy: Obsidian jako Lightweight Knowledge Base

*Zdroj: YouTube video "Obsidian + Cloud Code jako RAG bez vektorové databáze"*

### Hlavní postupy:

**1. Struktura vaultu:**
- `raw/` — Staging area pro nesetříděný obsah (clipped stránky, poznámky)
- `wiki/` — Organizované, strukturované znalosti
- `cloud.md` — Prompt pro Claude/Code jak procházet a formátovat wiki

**2. Index systém:**
- Hlavní `index.md` odkazuje na per-wiki indexy
- Umožňuje rychlý přehled bez procházení stovek souborů
- Minimalizuje token/tool calls — model má jasnou cestu k obsahu

**3. Ingestion workflow:**
- Obsidian Web Clipper → ukládá do `raw/`
- Local Images plugin — stahuje obrázky lokálně
- Claude/Code může automaticky generovat wiki z raw MD

**4. Automatizace:**
- Claude/Code researchuje web a generuje wiki stránky
- Případně vytváří nové wiki z existujících raw souborů
- Vše human-readable, prohlížitelné přímo v Obsidianu

### Přínosy vs tradiční RAG:

| Aspekt | Obsidian + Claude | Vektorová DB RAG |
|--------|-------------------|------------------|
| Náklady | Nízké (jen API calls) | Vyšší (infrastruktura) |
| Prototypování | Rychlé | Složitější |
| Škálovatelnost | ~tisíce dokumentů | Miliony+ |
| Human-readable | ✅ Ano | ❌ Ne |
| Latence | Závisí na LLM | Optimalizovatelné |
| Maintenance | Nízká | Vyšší |

**Kdy použít:**
- ✅ Solo operátoři, malé týmy
- ✅ < tisíce dokumentů
- ✅ Potřeba rychlého prototypování
- ✅ Priorita human-readable formátu

**Kdy přejít na vektorovou DB:**
- ❌ Miliony dokumentů
- ❌ Striktní latency požadavky
- ❌ Striktní cost constraints

## 🔧 Aktualizace našeho workflow dle vide

### Co už máme podobně:
- ✅ Denní paměťové soubory (místo `raw/`)
- ✅ MEMORY.md jako kurátorovaná paměť (místo `wiki/`)
- ✅ Automatický archive/summary systém

### Co můžeme zlepšit:

**1. Lepší indexace:**
- Vytvořit `INDEX.md` v rootu paměti
- Per-téma indexy (projekty, technologie, rozhodnutí)
- Pravidelná aktualizace (měsíčně?)

**2. cloud.md pro OpenClaw:**
- Vytvořit `AGENTS.md` variantu s pravidly pro procházení paměti
- Definovat priority: MEMORY.md > recent daily > archive

**3. Web clipping integrace:**
- Nastavit Obsidian Web Clipper → automaticky do `memory/inbox/`
- Cron job pro zpracování inboxu

**4. Structured vs unstructured:**
- `memory/inbox/` — raw vstupy
- `memory/YYYY-MM-DD.md` — denní logy
- `MEMORY.md` — distilled knowledge
- `projects/` — projekt-specific
